# セキュリティ設計

## スコープ

本書はプロフィール分離と、将来実装する保存パスワード機能の境界を定義する。初期版はパスワードを保存・自動入力しない。

## プロフィール分離

- プロフィール一覧（表示名とランダムUUID）のみをメインプロセスの `SharedPreferences` に保存する。
- WebViewは専用の `:browser` プロセスで動作する。WebView生成前にプロフィールUUIDのSHA-256由来サフィックスを `WebView.setDataDirectorySuffix` に設定し、Cookie、HTTPキャッシュ、DOM storage等を別ディレクトリに置く。
- 別プロフィールへ移る際はブラウザプロセスを終了する。WebViewのデータディレクトリはプロセス内で変更できないため、同一プロセスで切り替えない。
- Androidバックアップを無効化し、プロフィールデータがクラウドバックアップへ意図せず含まれないようにする。

これはOSユーザー間のような強い敵対的分離ではない。同じアプリUID、端末をroot化した攻撃者、侵害されたWebView実装からの分離は保証しない。

## Webコンテンツ

- 通常の遷移はHTTPSを既定とし、アプリのcleartext通信を無効にする。
- JavaScriptとDOM storageは現代的サイトとの互換性のため有効にするが、WebViewからのファイル／content URIアクセスは無効にする。
- JavaScript bridgeは追加しない。外部Intent、証明書エラー回避、ファイル選択を追加する場合は個別に脅威分析する。

## 保存パスワード（将来設計、未実装）

1. Android Keystore内にプロフィールごとのAES-256-GCM鍵を生成する。鍵素材をアプリストレージへ書き出さない。
2. origin、ユーザー名、パスワードを認証付き暗号で暗号化し、ランダムnonceと暗号文だけをアプリ内部DBに置く。originとプロフィールIDを追加認証データへ含め、レコード差し替えを検出する。
3. 自動入力はAndroid Autofill/認証情報APIを優先し、DOMへの汎用JavaScript注入は行わない。保存・更新前にユーザーへ明示確認する。
4. 任意設定で鍵利用時に端末認証を要求する。画面キャプチャ抑止、クリップボード非使用、ログ・クラッシュレポートから資格情報を除外する。
5. プロフィール削除時に暗号文、WebViewディレクトリ、Keystore鍵を削除する。鍵削除による暗号学的消去を行う。
6. エクスポート／同期は初期対象外。将来追加時は別のユーザーパスフレーズ由来鍵、バージョン付き形式、改ざん検出、レート制限を必須とする。

## 検証項目

- 二つのプロフィール間でCookie、localStorage、キャッシュ、認証状態が共有されないこと。
- プロフィール切替時に旧ブラウザプロセスが残らないこと。
- HTTP、TLSエラー、危険な外部スキーム、悪意あるダウンロード名を対象にしたテストを追加すること。
- 保存パスワード実装時は暗号方式、鍵ローテーション、バックアップ、端末移行を第三者レビューすること。
